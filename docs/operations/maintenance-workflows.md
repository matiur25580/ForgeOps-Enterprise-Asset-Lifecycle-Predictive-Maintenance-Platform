# Maintenance operations API

ForgeOps maintenance endpoints are mounted under `/api/v1/maintenance`. All endpoints require a verified bearer access token. Tenant identity comes from the token; request-supplied tenant IDs are never accepted.

## Work orders

| Method | Endpoint | Access | Purpose |
|---|---|---|---|
| GET | `/technicians?facilityId=:id` | Owner, admin, manager | List active technicians assigned to an in-scope facility |
| GET | `/work-orders` | Authenticated | Paginated work order queue; technicians see only work assigned to them |
| POST | `/work-orders` | Owner, admin, manager | Create corrective, preventive, or inspection work |
| GET | `/work-orders/:workOrderId` | Authenticated | Read one in-scope work order |
| PATCH | `/work-orders/:workOrderId` | Manager; assigned technician for limited fields | Update work, assignment, schedule, status, effort and completion notes |

### Work order lifecycle

- `open -> assigned -> in_progress -> on_hold -> in_progress -> completed`
- `open -> cancelled`, `assigned -> cancelled`, `in_progress -> cancelled`, `on_hold -> cancelled`
- Completed and cancelled records are terminal.
- Technicians can change status, actual hours and completion notes only on work orders assigned to their own user ID.
- Managers can edit operational fields and assign only active technician accounts that are assigned to the same facility.
- Work orders are tenant-scoped, and manager/technician access is facility-scoped.

Create example:

```json
{
  "facilityId": "64f000000000000000000001",
  "assetId": "64f000000000000000000002",
  "title": "Inspect cooling pump vibration",
  "type": "corrective",
  "priority": "high",
  "dueAt": "2026-12-01T09:00:00.000Z",
  "estimatedHours": 2
}
```

Work order numbers are generated by the API. Clients must not choose their own number.

## Preventive maintenance plans

| Method | Endpoint | Access | Purpose |
|---|---|---|---|
| GET | `/maintenance-plans` | Authenticated | List plans in the caller's scope |
| POST | `/maintenance-plans` | Owner, admin, manager | Create a recurring maintenance plan |
| PATCH | `/maintenance-plans/:planId` | Owner, admin, manager | Update recurrence, assignment or active state |
| POST | `/maintenance-plans/:planId/generate` | Owner, admin, manager | Generate a work order when the plan is due |

Supported frequencies: `daily`, `weekly`, `monthly`, `quarterly`, `yearly`, with an integer interval. The API calculates the next due date in UTC calendar time. A plan cannot generate a work order before `nextDueAt`; successful generation advances the recurrence and links the generated work order to the plan and scheduled occurrence.

A unique compound index on tenant, plan and scheduled occurrence prevents duplicate generated records for the same plan occurrence. The current release exposes an authenticated generation endpoint; it does not yet run a background scheduler automatically. The Angular Maintenance workspace provides a work order queue, assignment-aware creation, technician status actions, recurring plan creation, pause/activate controls and due-work-order generation.

## Audit and validation

Create/update/generation actions create tenant-scoped audit events. Validation rejects malformed IDs, unsupported enum values, invalid asset/facility combinations and technicians not assigned to the selected facility. Duplicate tenant-scoped work-order numbers and plan codes return the shared resource-conflict response.

## Verification

Run `npm test` to execute the API unit/regression and MongoDB-memory integration suites. Maintenance integration coverage verifies work-order creation, technician self-service boundaries, status transitions, recurrence advancement and cross-facility asset rejection.
